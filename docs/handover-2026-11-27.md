## How to work this document

- **Read `CLAUDE.md` first**, in full. It has the architecture, the invariants and the deployment rules. The rules
  that matter most here:
  - JS changes and `routes.php` changes need a `<version>` bump in `facewright_bridge/appinfo/info.xml`, and route
    changes also need a container restart. Otherwise you see 404s or old JS, while the source looks right.
  - `occ upgrade` also applies pending App Store updates. On dev that is fine.
- **Dev only.** The compose stack in this repo (`docker compose ...`, `dev/README.md`) is where you work and test.
  **Never touch the live instance.** That includes `make build` / `make run`: on this host they hit the live ExApp
  container. Deploying to live is the user's step, with their go-ahead.
- **Nothing is pushed** (this repo or the fork) without the user's go-ahead. Commit locally.
- **One commit per task** in this repo, with the attribution lines the session gives you. Commit before running
  `dev/run-all.sh`, because `rollback-drill.sh` refuses to run with uncommitted changes in `facewright_bridge/`.
- **Check outputs, not exit codes.** For every behaviour change, show that the old code fails the check and the new
  code passes it, where that is possible.
- Record what you measured under each task's "Done" heading in this file when you finish. Keep it short: what was run
  and what came out.

### T3b. Translatable strings in `js/people.js` (item 12)

**Scope:** `js/people.js` only. `admin.js` and `personal.js` (about 40 strings) stay as they are. List them under
"Follow-ups" below and do not do them.

The page has no build step, so `@nextcloud/l10n` cannot be imported. Use Nextcloud's globals `t()` and `n()`.

- **First check that they exist on this page:** in headless Chromium on the People page, `typeof t` and `typeof n`
  must both be `'function'`. If they are not, stop and report back.
- **Escaping, the trap here.** `t(app, text, vars)` HTML-escapes substituted values by default. `people.js` writes
  text through `textContent` (`h()` never sets `innerHTML`; `docs/people-ui-review.md`, "Reviewed and fine"), so
  escaped values would show as `&amp;` or `&quot;` in names. Every call that has `vars` must pass `{ escape: false }`
  as the options argument. That is the fifth argument of `t`, and the sixth of `n`; read the signature in the
  Nextcloud server's `core/src/OC/l10n.js` for the version on dev. Wrap it in two local helpers so no call site can
  forget:

  ```js
  var APP = 'facewright_bridge';
  function tr(text, vars) { return t(APP, text, vars || {}, undefined, { escape: false }); }
  function trn(one, many, count, vars) { return n(APP, one, many, count, vars || {}, { escape: false }); }
  ```

  Then check with a person named `A & B "quoted"`: the name must show verbatim in the people list, the person
  header, and the merge and delete dialogs.
- **Whole sentences, not pieces.** Strings built by concatenation (for example around lines 565, 587 to 590, 610 and
  639: the selection count, the merge and delete confirmations) become one string per sentence with `{placeholders}`,
  so a translator can reorder them. Leave numbers and names out of the source string.
- **`plural()`** (`count.toLocaleString() + ' ' + noun`) becomes `trn('{count} face', '{count} faces', count, {count:
  count.toLocaleString()})` at each call site, or a small wrapper. Nouns must not be passed around as English words
  any more: the `nouns[0]` / `nouns[1]` pattern at line 565 has to carry the full plural pair instead.
- **`personLabel()`** returns `“Name”` or `an unnamed person`. The curly quotes are locale-specific: make it
  `tr('“{name}”', {name: person.title})` and `tr('an unnamed person')`.
- Toasts, button labels, `aria-label`s, `title`s, placeholders and dialog headings all count. Strings that come from
  the server (OCS error messages) are not in scope.
- **Server side:** add `\OCP\Util::addTranslations('facewright_bridge');` in `PageController::index()` next to
  `addScript`. With no `l10n/` folder it changes nothing, but translations then load once one exists. Do not create
  an `l10n/` folder or any translation files.
- **Check that nothing changed for English:** before the change, record every visible string the page shows in each
  view and dialog (people list, a person, unassigned, ignored, photo view, merge, delete, move, the suggestions panel,
  toasts after an action). Use headless Chromium and dump `document.body.innerText` plus `aria-label` / `title`
  attributes per view, scripted, into the scratchpad. Record the same after the change and diff. The only allowed
  differences are ones you list and explain in "Done" (for example plural fixes).
